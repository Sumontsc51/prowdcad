# ProwdCAD v2 — usability and bug review (2026-11-10)

Reviewed at `b375cdf` on `v2`. Method: read the web shell (`apps/web/src`), drove the app in headless
Chromium as a new user would (dialogs, keyboard, menus, small windows, file drop), and ran a random-input
"monkey" test (clicks, drags, hotkeys, menu and context-menu commands, undo/redo; 18 seeds, 600–900 actions
each) watching for page errors, broken renders and error toasts.

Baseline before any change: typecheck clean, kernel 333 / 333, e2e 350 / 350, hotkeys 111 / 111.

## 1. Bugs fixed

| # | Bug | Where | Fix |
|---|---|---|---|
| 1 | **A failed operation left the document half-changed.** `Document.transact` did not roll back when the op threw: the style kept whatever was mutated before the error, and an undo step for that broken state was recorded. The user saw an error toast that reads as "nothing happened". Found through Delete pleat on a stacked dart / pleat piece. | `packages/kernel/src/model/doc.ts` | A top-level step that throws restores the style, records no undo step and keeps the redo history. New test `test/transact.test.ts` (fails on the old code). |
| 2 | **Enter on a focused Cancel button pressed OK.** In "Discard unsaved changes?", Tab → Cancel → Enter discarded the work. | `ui/dialog.ts` | Enter on a focused button presses that button. |
| 3 | **Tab walked out of an open dialog** onto the buttons behind it. | `ui/dialog.ts` | Focus trap; a dialog without fields focuses its primary button. |
| 4 | **Hotkeys stopped after clicking a checkbox** (e.g. Nested view): focus stayed in the checkbox, which counted as "typing". | `ui/dom.ts`, `main.ts` | Checkboxes / radios are not text fields; mouse clicks on buttons and checkboxes hand focus back, so the next Enter / Space reaches the tool instead of re-pressing the button. |
| 5 | **Every Save added a hidden undo step** ("Attach preview"). Ctrl+Z right after Save undid nothing visible and marked the file unsaved. | `actions/file.ts` | Save refreshes the thumbnail without an undo step. File ▸ Attach preview thumbnail is still undoable. |
| 6 | **"Keep for later" lost the backup.** Closing the tab without edits deleted it; editing overwrote it after 30 s. | `actions/file.ts` | A kept backup is parked under its own key until it is restored or discarded. |
| 7 | **Auto-backup failed silently** when browser storage was full or blocked. | `actions/file.ts` | One warning toast. |
| 8 | **Canvas froze after deleting a piece a tool was working on** (Dart / Pleat / Slash mid-construction): every render threw `No piece …` until the tool was switched. | `app.ts` | The tool's draft is reset when a piece it may reference disappears; a render that throws resets the tool once and redraws. |
| 9 | **Dropping a file on the window navigated the browser away** from the app. | `main.ts`, `actions/file.ts` | Drag and drop opens a `.prowd.json` style (after the unsaved-changes question) or imports DXF + RUL / SVG / PLT. |
| 10 | **Long menus ran off short screens** (Seam: 23 rows, 700 px tall) and sub-menus near the bottom opened below the window. | `ui/menu.ts`, `styles.css` | Menus tighten, then scroll; sub-menus and long context menus are placed on screen. |
| 11 | **Right dock was clipped in narrow windows** (≈ 900 px): buttons and the title cut off. | `styles.css` | The centre column can shrink; the dock narrows to 220 px; the menubar adapts. |
| 12 | Esc did not close a tool flyout. | `ui/palette.ts`, `main.ts` | It does, and the flyout stays on screen. |

## 2. Usability changes

- **Find a command (Ctrl+K)** — one search box over every command and tool (about 300). Type "notch",
  "seam corner", "export dxf"; ↑ ↓ and Enter to run. Each row shows the menu it lives in and its shortcut;
  a command that needs a selection says so. Also reachable from the box in the menubar and Help.
- **Keyboard shortcuts (F1)** is the same list filtered to commands with a key, searchable — it was a
  wrapped block of plain text.
- **Quick access** in the menubar: Undo, Redo, Save, Zoom to fit. The tooltips name the step
  ("Undo: Move point"); Save shows a dot while there are unsaved changes.
- **Tool tooltips** appear quickly and list the tool's key and the other tools in the same group with
  their keys ("Right-click or hold for: …").
- **Status hint**: hovering the (often truncated) tool hint shows all of it, one step per line.
- **Drop to open** overlay while a file is dragged over the window.
- Visible keyboard focus ring on buttons.

## 3. Found, not changed

1. **Delete pleat can fail** with "Pleat axis must cross the sew line twice" when a later dart / pleat /
   fullness on the same piece can no longer be re-applied after the delete (`ops/pleats.ts::deletePleat`
   → `fullnessRewind`). With fix 1 the document is now untouched, but the pleat still cannot be deleted.
   Needs a decision: leave the later objects closed and report them, or refuse with a message that names them.
2. **Validation messages are shown as red errors** and logged to the console: "Edit to target: Add
   segments first", "Preview: Choose a measurement first", "Fold line must cross the piece". They are
   instructions, not failures; a `UserError` class shown as a neutral toast would read better.
3. **A step that changes nothing still records an undo step.** Dropping it needs a second
   `JSON.stringify` per step; worth measuring on an 80-size style first.
4. **Undo snapshots are full JSON copies** (200 kept). Fine now; a large graded style will make every
   step and the 30 s backup slower. localStorage (about 5 MB) will also stop holding the backup — IndexedDB
   would fix that.
5. **Resizing the window does not re-fit the view**, so the piece can end up off-centre.
6. **Menus cannot be driven from the keyboard** (arrow keys, Alt+letter). Ctrl+K covers most of the need.
7. The production bundle is one 800 kB chunk; the PDF / DXF exporters could be loaded on demand.
