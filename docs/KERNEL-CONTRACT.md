# ProwdCAD kernel — contract for module authors

Read `packages/kernel/src/model/types.ts`, `model/contour.ts`, `model/doc.ts`, `model/factory.ts`,
`geom/poly.ts`, `geom/vec.ts`, `ops/seam.ts` and `test/foundation.test.ts` before writing anything.

## Conventions (do not change)
- **Units**: mm, float64. Frame is y-UP (mathematical). Display units are a UI concern.
- **Piece = sew line (master) + derived cut line.** `piece.sew` is the only boundary you edit.
  The cut line is regenerated by `ops/seam.ts::computeCutLine` and read via `Document.resolvePiece()`.
- **Anchors**: `kind:'grade'` (corners / rule carriers / notch-dart-seam anchors) vs `kind:'curve'`
  (intermediate). `smooth:false` = corner. Handles `hIn/hOut` are RELATIVE offsets; absent ⇒ centripetal
  Catmull-Rom supplies the tangent. Every span is a cubic Bézier under the hood (`resolveContour`).
- **Grading** is incremental per size: `inc[size_i] = abs[size_i] − abs[size_{i−1}]` in size-line order,
  `abs[base]=0`. Use `absoluteOffset / absoluteToIncremental / incrementalToAbsolute` from `model/contour.ts`.
  Curve points without explicit grading are interpolated proportionally between neighbouring grade points.
- **Segments**: segment k of a contour goes from `gradeIdx[k]` to the next grade anchor (`gradeSegment`).
  Seam allowance for segment k lives on `points[gradeIdx[k]].seamAfter` (undefined ⇒ `piece.seamDefault`).
- **Mutations** go through `doc.transact(label, style => {...})`. Nested transact = one undo step.
  Never mutate `doc.style` outside `transact`. Do not cache resolved geometry across transactions.
- **Ids** come from `newId(prefix)`. Never reuse an anchor id.
- **Live objects** (darts, pleats, notches, fullness) are NEVER baked into the sew contour as plain
  geometry: they reference anchor ids and are re-derived on resolve. Legs/edges they need on the sew
  contour are grade anchors flagged `flags.dartLeg` / `flags.pleatEdge` and must be kept in sync.
- Winding of `piece.sew` is not guaranteed. Use `isCCW`, `offsetOutward` (winding-agnostic).
- Tolerances: geometric equality 1e-6 mm; lengths reported to 0.01 mm; acceptance tests state their own.

## File ownership
Each module lives in `packages/kernel/src/ops/<module>.ts` (+ helpers in `src/ops/<module>/`) and tests in
`packages/kernel/test/<module>.test.ts`. **Do not edit `src/index.ts`** (the integrator adds exports).
Additive edits to `model/types.ts` are allowed ONLY as new optional fields on interfaces your module owns
(e.g. `Dart`, `Pleat`, `Notch`) — never rename/remove/restructure. Do not edit other modules' files.
If you need a geometry helper that belongs in `geom/`, add it to a NEW file `geom/<yourmodule>-geom.ts`.

## Testing
`cd packages/kernel && npx vitest run` and `npx tsc --noEmit -p .` must pass. Tests are plain Node, no DOM.
Write the spec's acceptance tests that belong to your module (numbered, e.g. `D3`) and assert exact numbers.

## Reporting
End with: implemented / stubbed (named functions that throw `NotImplemented` or return trivial results) /
assumptions (Gerber/TUKA-standard choices made where the spec is silent).
